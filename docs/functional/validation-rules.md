# 14. Validation Rules & System States

## Loading States

Every API call should have:

- Skeleton Loader
- Spinner
- Disabled Buttons

---

## Empty States

Display friendly empty state views with explicit Call-to-Action (CTA) buttons for:

- No Companies
- No Documents
- No Employees
- No Partners

---

## Error Handling

- Display friendly error messages.
- Never expose backend stack traces to end users.

---

## Validation Rules

Every form must validate:

- Before submission
- On change
- On blur
- Server-side validation fallback

---

## Success Messages

Standardized success feedback examples:

```
Company created successfully.
```

```
Employee added successfully.
```

```
Document uploaded successfully.
```

```
Invoice generated successfully.
```
